# NetSage Knowledge Base Documentation

The NetSage Knowledge Base embodies domain networking expertise structured across three distinct tiers:
1. **Static Domain Knowledge**: Immutable networking principles and axioms.
2. **User Diagnostic Facts**: Dynamic inputs asserted through interactive inquiries.
3. **Rule-Derived Facts**: Intermediate conclusions and terminal diagnoses generated by production rules.

---

## 1. Static Domain Knowledge Base (30 Verified Networking Axioms)

| ID | Key | Category | Statement | Diagnostic Relevance |
|:---|:---|:---|:---|:---|
| **F01** | `router_function` | `GENERAL` | A router connects a local area network (LAN) to external networks and routes IP packets. | If the local device cannot reach the router, no external internet communication is possible. |
| **F02** | `gateway_function` | `GATEWAY` | A default gateway provides an exit point from a local subnet to remote destinations. | An unreachable gateway pinpoints the fault to the local link or router rather than remote servers. |
| **F03** | `dns_function` | `DNS` | DNS translates human-readable domain names into numeric IP addresses. | Differentiates between total connectivity loss and name-resolution failure. |
| **F04** | `dhcp_function` | `IP_DHCP` | DHCP automatically leases IP configuration, subnet mask, default gateway, and DNS servers to clients. | DHCP failure prevents the client from obtaining valid IP configuration to communicate. |
| **F05** | `apipa_addressing` | `IP_DHCP` | An Automatic Private IP Address (APIPA) in 169.254.0.0/16 indicates an unfulfilled DHCP request. | Direct evidence that the client cannot communicate with any active DHCP server on the local link. |
| **F06** | `valid_config_requirement` | `GENERAL` | A host requires a valid IP address, subnet mask, and default gateway for routable network communication. | Validates whether basic host network stack initialization has succeeded. |
| **F07** | `unreachable_gateway_local_fault` | `GATEWAY` | An unreachable default gateway indicates a local layer-1, layer-2, or router crash problem. | Eliminates remote WAN or cloud service outages as the root cause. |
| **F08** | `dns_failure_domain_impact` | `DNS` | DNS resolution failure prevents accessing websites by hostname while raw IP access continues to function. | Signature symptom of DNS failure: pinging an external IP succeeds, but pinging domain names fails. |
| **F09** | `external_ip_connectivity_isolation` | `DNS` | Successful external IP ping confirms Layer 3 WAN routing and eliminates local gateway or ISP link failure. | Crucial boundary test: rules out physical link, gateway, and ISP layer-3 outages. |
| **F10** | `weak_wifi_instability` | `WIFI` | Low Received Signal Strength Indicator (RSSI below -75 dBm) causes frame drops and connection instability. | Identifies RF propagation limitations as the root cause of intermittent drops. |
| **F11** | `rf_attenuation_factors` | `WIFI` | Physical obstacles (concrete walls, metal) and distance severely attenuate 2.4 GHz and 5 GHz Wi-Fi signals. | Explains why Wi-Fi degradation is localized to specific rooms or physical locations. |
| **F12** | `packet_loss_consequence` | `PERFORMANCE` | Packet loss causes TCP retransmissions, head-of-line blocking, and catastrophic throughput degradation. | Distinguishes high-latency but intact links from damaged physical media or congested queues. |
| **F13** | `latency_impact` | `PERFORMANCE` | High Round-Trip Time (RTT) increases communication delay and degrades interactive applications. | Explains poor real-time performance (buffering, VoIP drops, gaming lag) despite nominal bandwidth. |
| **F14** | `network_congestion_causes` | `PERFORMANCE` | Heavy concurrent bandwidth consumption causes router bufferbloat, spiking latency and packet loss. | Distinguishes equipment breakdown from temporary multi-user bandwidth saturation. |
| **F15** | `multiple_device_correlation` | `ISP` | Simultaneous connectivity failure on multiple independent devices proves an infrastructure-level fault. | Distinguishes host-specific driver/OS misconfigurations from router or ISP-wide failures. |
| **F16** | `router_reboot_clears_state` | `GATEWAY` | Rebooting network hardware flushes routing tables, clears ARP caches, and resets exhausted NAT states. | If a reboot temporarily fixes the problem, router hardware exhaustion or firmware bug is diagnosed. |
| **F17** | `dns_server_misconfiguration` | `DNS` | An incorrect or unassigned DNS server IP in client network settings prevents all name resolution. | Focuses remediation on changing client or router DNS resolver addresses (e.g. to 8.8.8.8). |
| **F18** | `ip_subnet_mismatch` | `IP_DHCP` | An IP address outside the gateway subnet prevents direct Layer 2 ARP communication with the gateway. | Diagnoses invalid manual static IP configuration. |
| **F19** | `ethernet_wifi_isolation` | `WIFI` | Wired Ethernet connections bypass radio frequency interference and signal attenuation entirely. | If wired Ethernet works while Wi-Fi fails, the issue is exclusively wireless. |
| **F20** | `gateway_reachability_scope` | `GATEWAY` | Reaching the local default gateway only proves LAN integrity and does not guarantee WAN connectivity. | Prevents premature conclusion that internet works just because the router pings successfully. |
| **F21** | `wifi_association_vs_internet` | `WIFI` | Successful Wi-Fi association (layer 2) does not guarantee Layer 3 IP assignment or internet access. | Explains the common user condition 'Connected to Wi-Fi, No Internet Access'. |
| **F22** | `jitter_performance_degradation` | `PERFORMANCE` | Variable packet delay (jitter) and packet loss severely degrade streaming and voice calls. | Guides diagnosis for users reporting video conference stuttering or call drops. |
| **F23** | `dhcp_renewal_clears_lease` | `IP_DHCP` | Releasing and renewing a DHCP lease requests fresh IP parameters and clears stale lease assignments. | Primary first-line remediation step for IP assignment anomalies. |
| **F24** | `public_dns_fallback` | `DNS` | Configuring public recursive resolvers (e.g., 1.1.1.1, 8.8.8.8) bypasses ISP DNS outages. | Determines whether DNS issue is local configuration or upstream ISP resolver failure. |
| **F25** | `isp_outage_scope` | `ISP` | An ISP outage disrupts external IP routing and WAN PPPoE/DHCP links across an entire neighborhood. | Diagnoses scenarios where all local network devices fail to reach external IP targets. |
| **F26** | `hardware_power_cycle_flushes_capacitors` | `GENERAL` | A 30-second power cycle fully discharges power capacitors and forces complete hardware reboot. | Standard hardware recovery procedure for frozen networking gateways. |
| **F27** | `ip_vs_dns_orthogonality` | `DNS` | Layer 3 ICMP ping to an external IP operates completely independently of Layer 7 DNS name resolution. | Provides the definitive diagnostic test separating DNS faults from internet outages. |
| **F28** | `valid_ip_gateway_independence` | `GATEWAY` | A valid statically configured IP address does not guarantee that the default gateway is functional. | Ensures that validating host IP does not bypass checking gateway availability. |
| **F29** | `captive_portal_interception` | `GENERAL` | Captive portals intercept HTTP traffic and spoof DNS queries until web-based authorization completes. | Explains why device is connected with IP and DNS working, yet ordinary internet access is redirected. |
| **F30** | `mtu_black_hole_loss` | `PERFORMANCE` | MTU mismatches drop packets exceeding maximum transmission unit when Path MTU Discovery (PMTUD) fails. | Explains why ping works fine (small packets), but opening full web pages or file downloads hangs. |
